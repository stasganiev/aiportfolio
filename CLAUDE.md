# Сайт ganiev.pro

Личный сайт Стаса Ганиева: Senior 1С-разработчик, автор двух курсов для 1С-разработчиков, спикер. Сайт работает как точка доверия для трёх аудиторий (1С-разработчики, компании и организаторы, зарубежные коллеги).

## С чего начать сессию

1. Прочитать `work/TZ.md`: раздел 0 (порядок работы), текущий этап в разделе 9, разделы 11 (вопросы) и 12 (бэклог).
2. Выполнить `git status` и `git log --oneline -5`: Стас коммитит и пушит сам.
3. Не начинать этап, пока Стас не согласовал его описание в ТЗ.

Со Стасом общаемся по-русски.

## Как идёт работа

- Цикл одного этапа: Стас вычитывает этап в ТЗ, согласует, затем разработка, затем приёмка.
- Делается только то, что входит в согласованный этап. Всё остальное записывается в бэклог ТЗ (раздел 12).
- Отчёт по этапу: что сделано, что решено без Стаса, что проверено и каким способом, что нужно от него. Скриншоты в обеих темах на ширине 1440, 1366×768 (первый экран) и 390.
- Коммит только после приёмки. «Принято» и «закрой этап» означают локальный коммит. Перед коммитом смотреть `git log`: Стас мог закоммитить сам.
- Push только по просьбе Стаса. Разработка идёт прямо в `main`.
- Публикация запускается вручную (`deploy.yml`, `workflow_dispatch`). Автопубликацию по push, домен и DNS не трогать до этапа 11.
- Правку текста, которую Стас дал по макету, вносить и в мастер-тексты.
- В конце этапа обновить: статус этапа и журнал изменений в ТЗ, раздел «Состояние» здесь.
- Побочных файлов не оставлять. Заметки и черновики живут только в `work/`.

## Решения Стаса, которые легко нарушить

- Секции «КОНТУР» на сайте нет. Остаётся только название доклада в списке выступлений.
- Темы про MCP на странице спикера нет.
- На сайте нет ничего, за чем надо следить по датам: дат потоков, статусов набора, сезонных кнопок.
- Главная кнопка в hero одна на все языки: «Связаться», ведёт к контактам.
- Отзывы подписываются по образцу «Имя Ф., курс, поток N». Полных фамилий нет.
- В записи про 1C Romania нет слов «в одиночку» и нет сроков: сайт читают коллеги.
- Логотип это фирменный знак Стаса. Новых знаков и монограмм не придумывать, цвета знака не менять.
- В hero стоит небольшой портрет рядом с именем. Его размер утверждён.
- Ссылка на папку с фото на Google Диске и Taplink на сайт не выводятся.
- Форма обратной связи остаётся. Семья упоминается одной строкой, без имён.

## Языки

Три полных языка: английский по умолчанию (`/`), русский (`/ru/`), сербский латиницей (`/sr/`). Русский текст пишется первым и служит мастер-версией. Правка текста вносится во все три языка одним коммитом. Сербский текст вычитывает носитель языка, вычитку организует Стас.

## Окружение

- Windows 11, Node 24, npm 11.
- Python запускать через `python`, не `python3`. Есть Pillow, нет PyYAML и fontTools. YAML проверять через `npx --yes js-yaml <файл>`.
- Скриншоты: Chrome в режиме `--headless=new --screenshot`. Окно Chrome не бывает уже 500 px, поэтому телефонную ширину снимать через `work/concepts/frame.html` (iframe нужной ширины).
- Файлы в LF. При правке через Python открывать с `newline=""`, иначе git покажет файл переписанным целиком.
- Скрипт на Python с `\n` внутри строк не передавать через heredoc в Bash: строки рвутся. Записать скрипт в файл и запустить.
- С этой машины не открываются `cors.su`, `lad-corp.ru` и `proglib.io`. Ссылки на них проверяет Стас в браузере.

## Скиллы проекта

Лежат в `.claude/skills/`:

- `design-system`: токены и спецификации компонентов.
- `design`: логотип, иконки, баннеры. Генерация картинок требует ключ Gemini API.
- `stop-slop`: проверка текстов на признаки машинного письма.
- `ui-ux-pro-max`: чек-лист качества интерфейса. Поисковый движок (`scripts/`, `data/`) не установлен, команды поиска из его инструкции не работают.

В инструкциях скиллов пути указаны как `~/.claude/skills/...` и `python3`. В этом проекте скрипты лежат в `.claude/skills/<имя>/scripts/` и запускаются через `python`.
